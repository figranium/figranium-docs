Figranium offers two kinds of libraries. The **SDKs** connect your code to a running Figranium server, so you can save and run tasks, stream execution events, and manage schedules, captures, and Cabinets from JavaScript, Python, Swift, or Kotlin. **Fiptcha** is a standalone Node.js library that solves CAPTCHAs locally inside your own Playwright automation, with no Figranium server required.

## Choose an SDK

Every SDK wraps the same Figranium REST and Server-Sent Events API, so features match across languages. Pick the one that fits your stack.

<CardGroup cols={2}>
  <Card title="JavaScript SDK" icon="brand-javascript" href="/sdk/js/overview">
    `@figranium/sdk` for Node.js 18+ and modern browsers. TypeScript first, ESM and CommonJS, no runtime dependencies.
  </Card>

  <Card title="Python SDK" icon="brand-python" href="/sdk/python/overview">
    `figranium-sdk` for Python 3.9+. Sync and async clients built on `httpx`, with `TypedDict` types.
  </Card>

  <Card title="Swift SDK" icon="brand-swift" href="/sdk/swift/overview">
    `Figranium` package for macOS, iOS, tvOS, watchOS, and server-side Swift. Native `async`/`await`, zero dependencies.
  </Card>

  <Card title="Kotlin SDK" icon="brand-kotlin" href="/sdk/kotlin/overview">
    `dev.figranium:figranium` for Kotlin and Android API 23+. Coroutines on OkHttp, `Flow` streams, optional Android AppFunctions.
  </Card>
</CardGroup>

|  | JavaScript | Python | Swift | Kotlin |

## Install an SDK

<CodeGroup>

```bash npm (JavaScript)
npm install @figranium/sdk
```

```bash pip (Python)
pip install figranium-sdk
```

```swift Package.swift (Swift)
.package(url: "https://github.com/figranium/figranium-swift.git", branch: "main")
```

```kotlin build.gradle.kts (Kotlin)
implementation("dev.figranium:figranium:0.1.0")
```

</CodeGroup>

## What every SDK can do

- Save, update, version, and roll back tasks.
- Run tasks with runtime variables, or call `scrape`, `agent`, and `headful` directly.
- Stream live execution and selector events over Server-Sent Events.
- Manage schedules, captures, cookies, output credentials, and Cabinets.
- Open and inspect headful browser sessions.
- Administer settings such as API keys, AI providers, proxies, and theme.

## Before you start

<Steps>
  <Step title="Run a Figranium server">
    Every SDK talks to a running Figranium instance. Local installs listen on `http://localhost:11345` by default. See [Docker Compose](/docker-compose) to set one up.
  </Step>
  <Step title="Create an API key">
    Generate a key so the SDK can authenticate requests. See [API key](/api-key).
  </Step>
  <Step title="Follow your SDK's quickstart">
    Build and run your first task with the [JavaScript](/sdk/js/quickstart), [Python](/sdk/python/quickstart), [Swift](/sdk/swift/quickstart), or [Kotlin](/sdk/kotlin/quickstart) quickstart.
  </Step>
</Steps>

<Tip>
  Prefer calling HTTP directly? The [REST API](/rest-api) exposes the same endpoints the SDKs wrap.
</Tip>

## Fiptcha: local CAPTCHA solving

Fiptcha is the CAPTCHA engine behind Figranium, published as its own Apache-2.0 npm package. Unlike the SDKs, it doesn't call a Figranium server. You pass it a Playwright-compatible page, and it solves reCAPTCHA v2, hCaptcha, and Cloudflare Turnstile in place.

```bash
npm install fiptcha
```
