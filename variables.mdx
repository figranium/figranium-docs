Figranium uses a powerful variable system to make tasks reusable and dynamic. You can reference variables anywhere in a task using the `{$varName}` syntax, and combine them with JavaScript expressions for complex logic.

## Variable Syntax

Anywhere in a task (URL, Selectors, Action Values, Scripts), you can reference a variable using the `{$varName}` syntax.

**Example**:

- **Variable**: `query` = "Figranium"
- **Action**: Type into `input[name="q"]`
- **Value**: `{$query}`

When executed, Figranium replaces `{$query}` with "Figranium".

## Defining Variables

<Tabs>
  <Tab title="Task Variables">
    Define default values in the **Editor \> Variables** section.

    - **Types**: String, Number, Boolean.
  </Tab>
  <Tab title="Runtime Variables">
    Pass overrides via the API when triggering a task.

    ```json
    POST /api/tasks/:id/api
    {
      "variables": {
        "query": "new value"
      }
    }
    ```
  </Tab>
</Tabs>

## 1Password Login Variables

Connect a 1Password service account in **Settings > Connections** to use Login items in tasks. Figranium resolves credential variables on the server from the Login item whose website matches the task URL. See [Passwords](/passwords) for the Vault list and connection steps.

- `{$password}` and `{$uname}` use the password and username for the task URL's website.
- `{$passwords.example^com}` and `{$unames.example^com}` select a specific hostname. Replace each dot with `^`, for example `{$passwords.login^example^com}` for `login.example.com`.
- If no matching Login item exists, the required field is missing, or multiple items match, the task run fails instead of using an empty value.
- `password` and `uname` are reserved names. Do not define them as ordinary task variables or pass them as runtime variables.
- Resolved usernames and passwords are redacted from execution results and logs.

<Tip>
  Figranium can offer to save or update a Login item after you enter credentials in the [headful browser](/headful-browser#save-login-credentials). The prompt requires a connected 1Password service account.
</Tip>

## Variable Types

<CardGroup cols={2}>
  <Card title="Global Variables" icon="variable">
    Defined at the task level and accessible throughout the entire execution. Set defaults in **Editor \> Variables** or pass them at runtime via the API.
  </Card>

  <Card title="Task Variables" icon="list-check">
    Scoped to the current task execution. These include variables you define in the task settings and any values set during execution with the `set` action.
  </Card>

  <Card title="Loop-Local Variables" icon="rotate">
    Available only inside loop blocks. `loop.index`, `loop.item`, `loop.text`, and `loop.html` provide context for the current iteration.
  </Card>

  <Card title="Built-in Variables" icon="code">
    Figranium provides special variables like `{$now}` for the current timestamp and `block.output` for the previous action's result.
  </Card>
</CardGroup>

## Special Variables

Figranium provides several built-in variables:

  <Card title="`{$now}`" icon="clock">
    Current ISO timestamp.
  </Card>

  <Card title="`block.output`" icon="arrow-right">

  <Card title="`loop.index`" icon="code">

  </Card>

  </Card>

  <Card title="`loop.text`" icon="book">

    The HTML content of the current loop item.
  </Card>
</CardGroup>

## Dynamic Usage

You can use variables to build complex logic:

1. **URL Templating**: `https://example.com/search?q={$query}`
2. **Selectors**: `.item[data-id="{$itemId}"]`
3. **Scripts**: `const user = "{$username}";`

## Persistent Variables

The `set` action allows you to update variables during execution.

- **Action**: `set`
- **Var Name**: `counter`
- **Value**: `{$counter} + 1` (JavaScript expression)

This value persists for the remainder of the task execution.

## Handling Sensitive Values

Ordinary variable values are not masked or redacted in execution logs. Values you `Type` into an input, pass as a `{$variable}`, or return from a `javascript` block can appear in the execution record stored at `data/executions.json` (or the equivalent PostgreSQL table). Treat that record as sensitive. Credentials resolved from 1Password variables are redacted from results and logs.

For passwords, API tokens, and other secrets used in a login flow, we recommend:

<Steps>
  <Step title="Don't hard-code secrets as defaults">
    Default values are saved with the task definition and persist across executions and exports.
  </Step>
  <Step title="Pass secrets at runtime">
    Trigger the task via `POST /api/tasks/:id/api` with the secret in the `variables` payload. The value only lives in memory for that run and is not saved back to the task definition. See [REST API](/rest-api).
  </Step>
  <Step title="Reference the value once">
    Use `{$password}` directly in the `Type` action's **Value** field rather than copying it into intermediate `set` variables or `javascript` blocks, which increases the surface area where the value can be logged.
  </Step>
  <Step title="Rotate execution history">
    Delete runs that contain secrets from **Executions**, or purge everything via **Settings \> Advanced \> Clear execution history**. Figranium also auto-rotates the log at `MAX_EXECUTIONS` entries (default 500). See [Captures & Storage](/captures-and-storage).
  </Step>
  <Step title="Restrict access to the host">
    All execution data stays on your own machine or server. Because there is no in-app redaction, anyone with filesystem or database access to `data/executions.json` can read historical values. Follow [Security best practices](/security) to keep that data private.
  </Step>
</Steps>

<Tip>
  Output provider credentials saved under **Settings > Connections** (such as Baserow tokens) are stored separately from task variables. This section applies to values typed into pages during a scrape, not to those saved credentials.
</Tip>

<Tip>
  Use `block.output` to chain actions together. After a `javascript` block returns data, the next block can reference it with `{$block.output}` to build dynamic, multi-step workflows without intermediate variables.
</Tip>
