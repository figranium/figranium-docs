Fiptcha is the CAPTCHA runtime that powers [Figranium Browsers' CAPTCHA solving](/captcha-solving), packaged as a standalone Node.js library you can embed in any browser automation project. It runs inside the Playwright-compatible page you already have, using local vision models instead of a paid solving service.

## Supported challenges

| `captchaType` | Behavior |
| --- | --- |
| `recaptcha_v2` | Interacts with the checkbox and solves supported image-grid challenges locally when required. |
| `hcaptcha` | Interacts with the widget and solves supported image-grid challenges locally when required. |
| `turnstile` | Performs active-browser interaction and waits for a token. Does not use the vision path. |
| `distorted_text` | Captures the CAPTCHA image, runs local Florence-2 OCR, and fills the input. |

<Warning>
3×3 image-grid stability is currently limited. Dynamic 3×3 challenges, especially those that replace tiles after a selection, may be unreliable. 4×4 static grids are the more stable path.
</Warning>

Fiptcha cannot guarantee every challenge is solvable. CAPTCHA providers change their UI, challenge formats, and risk checks independently of the visible widget.

## What Fiptcha owns

Fiptcha does not launch a browser. Your application keeps control of browser lifecycle, contexts and sessions, navigation, when to run CAPTCHA handling, workflow-level retries, proxies, and persistence.

Fiptcha handles the CAPTCHA-specific runtime: token detection, widget interaction, grid solving, OCR, model downloads, resource checks, and the optional companion runtimes. No Figranium Browsers server, task schema, database, or UI is required.
