**Output Providers** allow Figranium to automatically push extracted data to external databases and services immediately after a task completes — no manual download or API polling required.

## Overview

After a task finishes extracting data, Figranium can automatically forward the result to a configured output destination. This creates a fully automated pipeline:

```text
Task runs → Extracts data → Pushes to Baserow table
```

This is useful for:

- Continuously populating a database with scraped data on a schedule.
- Building live dashboards that refresh from automated tasks.
- Feeding extracted data directly into other tools without custom ETL scripts.

## Baserow Integration

[Baserow](https://baserow.io) is a self-hosted, open-source alternative to Airtable. Figranium integrates with it to push extracted JSON data into a dedicated Baserow table that Figranium creates for each task.

### Prerequisites

1. A running Baserow instance (self-hosted or Baserow.io cloud).
2. A Baserow token that can list workspaces and create databases and tables in the target workspace. Database-only tokens can't provision a destination.
3. A saved task. Figranium uses the task ID to name the dedicated database.

### Step 1: Configure credentials

You can add credentials in two places:

<Tabs>
  <Tab title="From Settings">
    1. Go to **Settings \> API Keys**.
    2. Under **Database / Output**, click **Add API Key** and select **Baserow**.
    3. Enter a **Name**, **Base URL** (e.g., `https://api.baserow.io`), and your **API Token**.
    4. Save the credential.
  </Tab>
  <Tab title="From the task editor">
    1. Open a task and go to **Settings \> Output**.
    2. Click **\+ New** next to the Credential dropdown.
    3. Fill in the same fields and save.
  </Tab>
</Tabs>

<Note>
  Figranium validates the base URL to prevent requests to private or internal network addresses. If `ALLOW_PRIVATE_NETWORKS` is set to `false`, URLs pointing to private IP ranges (such as `10.x.x.x`, `172.16.x.x`, or `192.168.x.x`) are rejected. Redirect chains are also validated — if a Baserow instance returns a redirect, each hop is checked against the same blocklist. Additionally, sensitive headers like `Authorization` are automatically stripped if a redirect crosses to a different origin. See [Security best practices](/security) for details.
</Note>

### Step 2: Create a dedicated destination

Each task writes to its own dedicated Baserow database. You can't select an existing database or table, or enter a table ID manually.

<Steps>
  <Step title="Open task output settings">
    Open the task in the **Task Editor** and go to **Settings \> Output**.
  </Step>
  <Step title="Select provider and credential">
    Select **Provider**: `Baserow` and choose the credential you just created.
  </Step>
  <Step title="Create the database and table">
    Under **Dedicated Baserow destination**, choose a workspace and click **Create dedicated database and table**. Figranium creates a database named `Figranium - <task name> - <task ID>` with a table named `Results`. The editor then shows the new table ID as **Current table**.
  </Step>
  <Step title="Set error behavior">
    Choose **On Push Error**: `Ignore` (default) or `Log Error`.
  </Step>
  <Step title="Save the task">
    Save the task to activate the output provider.
  </Step>
</Steps>

<Warning>
  Figranium only pushes to dedicated destinations created from **Settings \> Output**. Tasks configured with a manually selected database or table ID before this change no longer push data. Open each affected task and create a dedicated destination to resume pushes.
</Warning>

### Step 3: Return extraction data

You don't need to create columns in advance. Before each push, Figranium reads the fields on the `Results` table. It then creates a long text field for every key in your data that doesn't have a matching field yet. Figranium matches field names exactly (case-sensitive).

Your extraction script must return either:

**A single object (inserts one row):**

```js
return {
  "Product Name": "Widget Pro",
  "Price": 29.99,
  "In Stock": true,
  "URL": window.location.href
};
```

**An array of objects (inserts multiple rows in a batch):**

```js
const rows = Array.from(document.querySelectorAll(".product-card")).map(card => ({
  "Product Name": card.querySelector(".title")?.innerText.trim(),
  "Price": parseFloat(card.querySelector(".price")?.innerText.replace("$", "")),
  "URL": card.querySelector("a")?.href
}));

return rows;
```

Any other shape, such as an empty array, a primitive, or an array that contains non-objects, fails the push.

### How data is sent

Figranium stores every value as text:

| Value type | Stored as |
| :-- | :-- |
| String | Unchanged |
| `null` or `undefined` | Empty string |
| Number, boolean, object, or array | JSON string (for example, `29.99`, `true`, or `{"a":1}`) |

| Extracted data shape | Baserow API call |
| :-- | :-- |
| JSON object `{}` | Single row via `POST /api/database/rows/table/{tableId}/` |
| JSON array `[{}, {}]` | Batch insert via `POST /api/database/rows/table/{tableId}/batch/` |

The integration uses Baserow's `user_field_names=true` parameter and authenticates with `Authorization: Token <your-token>`.

### Error Handling

By default, push failures are **ignored** — the execution is marked as successful even if the Baserow push fails. This prevents network blips from causing false task failures.

To log push failures as errors instead of warnings, set **On Push Error** to `Log Error` in the output settings.

Check the execution logs for output push status:

```text
[OUTPUT] Pushed data to baserow for execution exec_abc123
[OUTPUT] Push to baserow FAILED for execution exec_abc123: Baserow batch insert failed (403)
```
