title: "Stealth & Anti-Detection"
---

Figranium is designed to bypass modern bot detection systems by mimicking human behavior and masking automation fingerprints.

## **Stealth Flags**

When creating an **Agent** task, you can configure the following stealth settings in the **Advanced** panel:

| **Flag** | **Description** |
| :--- | :--- |
| **Natural Typing** | Simulates human-like keystroke delays and variances. |
| **Cursor Glide** | Moves the mouse smoothly to targets instead of teleporting instantly. |
| **Allow Typos** | Occasionally makes (and corrects) typing errors to appear more human. |
| **Idle Movements** | Simulates random mouse movements and scrolls during wait periods. |
| **Fatigue** | Gradually slows down interactions over long sessions to mimic user tiredness. |
| **Dead Clicks** | Performs occasional clicks on non-interactive areas of the page. |
| **Random Clicks** | Introduces slight randomization in click coordinates around the target element. |
| **Overscroll** | Slightly over-scrolls past target elements before correcting. |

## **Browser Fingerprinting**

Beyond behavioral simulation, Figranium implements several technical anti-detection measures:

-   **User Agent Rotation**: Automatically switch between common browser user-agent strings (currently based on Chrome v143).
-   **Viewport Randomization**: Vary the browser window size slightly for each execution.
-   **Stealth Plugin**: Integrates `puppeteer-extra-plugin-stealth` to hide Playwright/Chromium-specific properties (e.g., `navigator.webdriver`).
-   **Proxy Support**: Easily route traffic through residential or mobile proxies to mask your IP address.
-   **DNS-over-HTTPS**: When no proxy is configured, DNS queries are routed through Cloudflare's encrypted DoH resolver, preventing DNS-based tracking and leaks.
-   **WebRTC Leak Prevention**: WebRTC is configured to disallow non-proxied UDP connections, preventing IP address leaks through WebRTC channels.

## **CloakBrowser Engine**

Figranium ships with two interchangeable browser engines behind the same Playwright API:

- **Default** — stock Playwright Chromium patched at the JS level by `puppeteer-extra-plugin-stealth`. Ships with every install. No license required.
- **CloakBrowser** — a stealth-patched Chromium binary from [CloakBrowser](https://github.com/CloakHQ/cloakbrowser). Evasions are applied at the browser level rather than injected as scripts, which holds up better against fingerprinting stacks that inspect for late-patched properties.

Use CloakBrowser when target sites detect the default engine (for example, sites that fingerprint `navigator.webdriver` overrides or check for JS-level patches). For most workloads the default engine is enough — switch only if you see detection failures you can't work around with proxies, user-agent rotation, and the stealth flags above.

### Enable CloakBrowser

Set two environment variables on the Figranium server, then restart:

```text
USE_CLOAK_ENGINE=true
CLOAKBROWSER_LICENSE_KEY=cb_xxxxxxxx
```

- `USE_CLOAK_ENGINE=true` switches every Agent, Headful, and CLI run over to CloakBrowser. Leave it unset (or `false`) to keep the default engine.
- `CLOAKBROWSER_LICENSE_KEY` selects the latest patched binary. Without a key, CloakBrowser falls back to its free legacy binary.

The CloakBrowser Chromium binary is downloaded automatically during `npm install` when `USE_CLOAK_ENGINE=true` is set at install time. If you flip the flag after installing, run `npx cloakbrowser install` once to fetch the binary. Running `npx cloakbrowser login` writes the license key to `~/.cloakbrowser/license.key`, which CloakBrowser also reads at launch.

### Docker Compose

Uncomment the engine block in your `docker-compose.yml` and rebuild:

```yaml
services:
  figranium:
    image: ghcr.io/figranium/figranium:latest
    environment:
      - SESSION_SECRET=your_secure_random_string
      - USE_CLOAK_ENGINE=true
      - CLOAKBROWSER_LICENSE_KEY=cb_xxxxxxxx
```

All existing task settings — proxies, storage state, recording, stealth flags, headful VNC — carry over unchanged. You do not need to edit individual tasks when switching engines.

## **Cookie-Consent Auto-Dismissal**

Every Agent-mode page automatically clicks through common cookie-consent banners so your task can interact with the real page immediately, without you having to author a Click block for every consent dialog you might hit.

Figranium injects the community-maintained [`idcac-playwright`](https://www.npmjs.com/package/idcac-playwright) ruleset (a Playwright port of the "I don't care about cookies" browser extension) into every page in the Agent browser context. The script runs on the page's `domcontentloaded` event and looks for known consent-banner selectors from OneTrust, Cookiebot, TrustArc, Quantcast, and hundreds of other providers. When it finds one, it clicks the **reject** or **close** button — never **accept** — and lets your task continue.

- **Scope**: Agent mode only. Headful and Scrape modes do not dismiss consent banners (Headful is for human interaction; Scrape doesn't render banners at all because there is no browser).
- **Protocols**: Applies to `http://` and `https://` pages. `file://` and `data:` URLs are skipped by the underlying ruleset.
- **Timing**: The click happens after the DOM is parsed but before your first action block runs against the page, so subsequent selectors don't need to account for the banner overlay.
- **Failure mode**: If no matching banner is present, or the ruleset can't identify a reject button, the script no-ops silently and your task runs as usual. You can still add an explicit `Click` block if a site's banner isn't covered.

There is no configuration flag for this feature — it is always on in Agent mode. If a site's consent dialog is not being dismissed, capture the banner's HTML from the headful browser and file an issue with the selector so it can be added upstream.

## **Best Practices**

1.  **Enable Human Typing**: Always use this for login forms and search bars.
2.  **Vary Wait Times**: Use the `wait` action with small random variations instead of fixed durations.
3.  **Use Residential Proxies**: Essential for scraping sites with aggressive IP-based blocking.
4.  **Rotate User Agents**: Keep your automation from appearing as a single, static device.
