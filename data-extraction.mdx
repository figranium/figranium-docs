title: "Extraction Scripts"
---

Figranium offers powerful tools to extract structured data from web pages. The extraction process runs **after** all automation steps are complete.

## **Visual field mapping (default)**

Every task now opens its extraction editor in **Visual** mode. Instead of writing JavaScript, you list the fields you want and point each one at an element on the page. Figranium generates the underlying extraction script for you and keeps it in sync as you edit.

Visual mode is the right choice when:

- You are pulling a fixed set of named values (title, price, author, image URL, etc.).
- You want to build the mapping by clicking elements in the [Headful Browser](/headful-browser) rather than reading HTML.
- You do not need custom logic, conditionals, or post-processing between the DOM read and the returned value.

### Configuring a field

Open the **Extraction Script** block on the canvas (or the Extraction tab in **Task Settings**), keep the mode toggle on **Visual**, and click **Add Field**. Each field has four inputs:

| Input | What it does |
|:---|:---|
| **Name** | The key used in the returned JSON (e.g. `title`, `price`). |
| **Selector** | A native CSS selector. Passed straight to `document.querySelector` / `document.querySelectorAll`. Variables like `{{query}}` are interpolated. |
| **Attribute type** | What to read from the matched element: `Text` (textContent, trimmed), `HTML` (innerHTML), `Input Value` (`el.value`, falling back to text for non-inputs), or `Attribute` (any named attribute). |
| **Attribute name** | Only shown when the type is `Attribute`. The attribute to read, e.g. `href`, `src`, `data-id`. |
| **Multiple (list)** | Off returns the first match or `null`. On returns an array of every match. |

### Picking selectors from the page

Next to each field's selector input is a target icon that opens the [Headful Browser](/headful-browser) in inspect mode. Click any element and Figranium writes the selector back into the field, along with a row of alternative candidates you can swap in with one click.

Extraction scripts run through the browser's native `document.querySelector`, which does not understand Playwright's `:has-text(...)` pseudo-selector. Figranium filters those candidates out of the pick list for extraction fields so you never end up with a selector that works in the inspector but returns `null` at extraction time. Action blocks (Click, Type, etc.) still receive the full candidate list, because Playwright runs those.

### Example

Three fields — `title` (text), `price` (text), `image` (attribute `src`, single match) — generate this script under the hood:

```javascript
return {
  "title": (() => { const el = document.querySelector(".product-title"); return el ? el.textContent.trim() : null; })(),
  "price": (() => { const el = document.querySelector(".price-tag"); return el ? el.textContent.trim() : null; })(),
  "image": (() => { const el = document.querySelector(".product-image"); return el ? el.getAttribute("src") : null; })()
};
```

Flip **Multiple (list)** on and the field switches to an array:

```javascript
"tags": Array.from(document.querySelectorAll(".tag")).map(el => el.textContent.trim()),
```

### Switching to JavaScript mode

The mode toggle at the top of the editor flips between **Visual** and **JavaScript**. Switching to JavaScript surfaces the auto-generated script in a full code editor, where you can edit it freely — add filters, reshape the object, call `$$data.html()`, whatever you need. Tasks that were created before Visual mode existed, or tasks where you have hand-written a script, open in JavaScript mode automatically so your code is never hidden behind the field list.

<Tip>
  Switching modes does not delete anything. Your field list stays intact when you jump to JavaScript, and jumping back to Visual replaces the script with the freshly generated one from your fields. If you edited the script by hand, keep the task in JavaScript mode so those edits are not overwritten.
</Tip>

## **Extraction Script (JavaScript mode)**

Every task includes an **Extraction Script** field in the editor. This JavaScript code runs in the browser context to parse the final page state.

### **Input**

The script has access to:

- `document`: The DOM of the page.
- `$$data.html()`: A helper to get the raw HTML string (including Shadow DOM if enabled).
- `variables`: Any runtime variables defined in the task.

### **Output**

The script must return a value (String, Object, Array). This value is saved as the `result` of the execution.

- **JSON**: Automatically formatted.
- **CSV**: If `extractionFormat` is set to `csv`, Figranium attempts to convert an array of objects to CSV.

### **Example: Extracting a Product List**

```text
// Get all product cards
const products = Array.from(document.querySelectorAll(".product-card"));

// Map each card to an object
const data = products.map((card) => {
  const title = card.querySelector(".title")?.innerText.trim();
  const price = card.querySelector(".price")?.innerText.trim();
  const link = card.querySelector("a")?.href;

  return { title, price, link };
});

return data; // Returns an array of objects
```

### **Example: Extracting a Single Value**

```text
const price = document.querySelector(".main-price").innerText;
return { price };
```

## **DOM cleaning**

Before your extraction script runs, Figranium cleans the page HTML to remove noise and reduce payload size. This cleaned HTML is what you receive via `$$data.html()` and what is sent to AI providers when generating selectors or scripts.

### What is removed

The following elements are stripped entirely:

`script`, `style`, `link`, `meta`, `noscript`, `svg`, `canvas`, `iframe`, `object`, `embed`, `applet`, `param`, `source`, `track`

### What is kept

Only attributes that are useful for extraction are preserved:

- Identification: `id`, `class`, `name`
- Content: `href`, `src`, `alt`, `title`, `value`, `placeholder`, `content`, `datetime`
- Semantics: `aria-label`, `type`, `for`, `action`, `method`, `selected`, `checked`, `disabled`
- Table structure: `colspan`, `rowspan`, `scope`
- All `data-*` attributes (e.g., `data-id`, `data-price`, `data-sku`)

All other attributes are removed to keep the HTML compact and focused on extractable content.

### Shadow DOM support

If your target page uses Shadow DOM (common in web components), Figranium includes shadow root content by default. Shadow roots are serialized as `<template data-shadowroot="open">` elements inside the cleaned HTML, so your extraction scripts can traverse them like regular DOM nodes.

You can disable Shadow DOM inclusion in the task settings if it is not needed.

## **AI script generation**

You can have Figranium write extraction scripts for you using AI. Instead of writing JavaScript by hand, describe what you want to extract in plain language and the configured AI provider generates a working script.

### How to use it

1. Open a task in the editor.
2. Click the **Extraction Script** block on the canvas.
3. In the script modal, click the **Generate** button (sparkle icon) at the top of the editor.
4. Type a description of the data you want — for example, "extract all article titles and links" or "get the price and availability from the product page".
5. Press **Enter** or click **Generate**. The AI returns a script and inserts it into the editor.
6. Review the generated script, make any adjustments, and save.

The generation uses the AI provider fallback chain: Gemini → OpenAI → Claude → Ollama. At least one provider must be configured in **Settings \> System \> API Keys**. You can change the preferred model for each provider in **Settings \> System \> AI Models**.

For full details on API endpoints, system prompt rules, and advanced prompt examples, see the dedicated [AI Extraction Script Generation](/extraction-script-generation) guide.

<Tip>
  The generated script is standard JavaScript that runs via `page.evaluate()`. You can edit it freely after generation — it is not locked or managed by AI after insertion.
</Tip>

## **Handling dynamic content**

If the page loads content dynamically (AJAX), ensure your task includes `wait` or `wait_selector` actions _before_ the extraction script runs. The script executes only after the last action completes.

## **CSV Formatting**

If you select **CSV** as the output format:

1. Ensure your script returns an **Array of Objects**.
2. Keys in the first object become the CSV headers.
3. Figranium handles quoting and escaping automatically.

```text
return [
  { name: "Item 1", price: 10 },
  { name: "Item 2", price: 20 },
];
// Result:
// name,price
// "Item 1",10
// "Item 2",20
```
