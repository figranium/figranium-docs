**Figranite** is the high-performance, deterministic workflow interpreter at the heart of Figranium. It is a purpose-built execution kernel responsible for transforming abstract block definitions into sentient-like browser behavior. 

Unlike standard automation scripts that merely execute a linear sequence of commands, Figranite acts as a state-machine interpreter. It simulates human intent, navigating the web with the precision of a machine and the nuance of a human.

## Core Philosophy

The engine is built on three foundational pillars:

1.  **Deterministic Execution:** Every action, loop, and condition must resolve predictably, even in the chaotic environment of the live web.
2.  **Human Physics Simulation:** Automation must be indistinguishable from human interaction to bypass modern bot-protection systems.
3.  **Stateful Context:** The engine must maintain a complex, evolving state across nested loops, variables, and error boundaries.

## Architectural Components

The Figranite Engine is composed of five highly coupled modules, physically located in `src/agent/figranite/`. Together, they form a single execution kernel.

| Component | Responsibility |
| :--- | :--- |
| **The Brain** | Handles the main execution loop, block-map jumps, state management, and error recovery. |
| **The Limbs** | Implements the specific logic for every action type (click, type, hover, wait, etc.). |
| **The Physics** | Simulates Bezier curves, randomized jitter, and fatigue-aware typing. |
| **The Logic** | Evaluates structured conditions and JavaScript expressions for branching logic. |
| **The Nervous System** | Builds block maps and resolves foreach/repeat inputs before execution begins. |

### 1. The Brain (`index.js`)

The entry point of the engine is the `runFigranite` function. It initializes the execution context, which acts as the "bloodstream" of the engine, containing the `page`, `logs`, `runtimeVars`, and `lastMouse` state.

Before executing a single action, the Brain calls upon the Nervous System to pre-calculate a complex jump-map (`buildBlockMap`). This map allows the engine to handle nested `if/else` logic, `while` loops, and `foreach` iterations without relying on deep recursion, ensuring high performance and stability.

The Brain then enters a `while` loop, iterating through the actions based on the pre-calculated jump-map. It handles asynchronous error bubbles (`on_error` blocks) and maintains a consistent execution state across these jumps.

### 2. The Limbs (`action-handler.js`)

When the Brain determines which action to execute next, it delegates the work to the Limbs. The `executeAction` function is a massive switch statement that handles every supported block type.

The Limbs are responsible for translating the abstract intent of a block (e.g., "click this button") into concrete Playwright commands. However, it rarely calls Playwright directly for physical movements. Instead, it relies heavily on the Physics module to ensure the action is performed stealthily.

### 3. The Physics (`human-interaction.js`)

This module is perhaps the most irreplaceable part of the codebase. It implements the "physics" of the agent, ensuring that every interaction feels organic.

Key simulations include:
*   **Bezier-Curve Cursor Movements:** Mouse movements are not straight lines. They follow calculated Bezier curves with randomized control points to simulate the natural arc of a human hand.
*   **Randomized Jitter:** Micro-movements and hesitations are injected into the cursor path.
*   **Fatigue-Aware Typing:** Typing speeds vary naturally, with occasional pauses and simulated typos (if enabled) to mimic human fatigue and thought processes.
*   **Overshoot Scrolling:** Scrolling actions often overshoot the target slightly before correcting, a common human behavior.

### 4. The Logic (`logic-handler.js`)

The Logic module evaluates the conditions that dictate the flow of the state machine. It handles the `evaluateCondition` function, which processes structured conditions (e.g., "element exists", "text contains") and custom JavaScript expressions.

This module ensures that the Brain knows exactly when to jump to an `else` block, when to terminate a `while` loop, or when to trigger an `on_error` handler.

### 5. The Nervous System (`helpers.js`)

The Nervous System performs critical pre-processing tasks. Its primary function is `buildBlockMap`, which scans the flat JSON array of actions and maps out the start and end points of every logical block.

It also handles the resolution of variables and templates (`{$variable}`) within `foreach` loops, ensuring that the engine can iterate over dynamic data structures seamlessly.

## Variable Scoping and State Management

Figranite manages a sophisticated runtime variable system. It handles template resolution, block-level outputs (`block.output`), and loop-specific contexts (`loop.index`, `loop.item`). 

The engine also includes optimization logic to pre-calculate which actions require DOM snapshots (`actionNeedsHtml`). This avoids the O(N²) performance hit of repeatedly stringifying the entire page when it isn't necessary.

## Conclusion

The Figranite Engine is not just a script; it is a full state-machine interpreter for a custom visual programming language. It is the dense, unyielding, and foundational core of Figranium, transforming a static list of instructions into a dynamic, human-like, and self-correcting browser workflow.
